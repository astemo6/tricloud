## 一、Y探长

### 基本信息

| 项 | 内容 |
|---|---|
| 全名/项目名 | **oci-helper**（作者自称"Y探长"，"Y"取自作者 ID Yohann0617） |
| GitHub | https://github.com/Yohann0617/oci-helper（Apache 2.0，约 760+ stars） |
| 作者 | GitHub 用户 Yohann0617；TG 机器人 @oci_helper，交流群 t.me/oci_helper_chat |
| 主要用途 | 甲骨文云（OCI）日常运维 + **免费实例批量抢机（ARM/AMD）** |
| 技术栈 | Spring Boot 3 + JDK 21 + Vue + SQLite，Docker 部署，Web 面板（默认端口 8818，默认账号密码均为 `yohann`） |
| 是否开源 | **是**，Apache 2.0，代码可审计 |

### 核心功能清单

1. 批量添加多个租户配置（模糊搜索、状态筛选）
2. 更改实例配置、引导卷配置
3. 一键附加 IPv6、一键放行所有端口
4. 一键开启免费 AMD 实例下行 500Mbps
5. 一键自动救援 / 缩小硬盘（默认 47GB）
6. 安全列表管理（1:1 复刻甲骨文官方面板出入站规则）
7. 实时流量统计（分钟级别）、配额查询
8. 按多个 CIDR 网段更换实例公网 IP（遇请求频繁自动跳过）
9. 多租户同时批量开机，后台持续运行直至成功
10. **断点续抢**：配置与任务存本地 DB，服务重启后自动继续
11. 多区号支持、一键自动更新、加密备份恢复
12. 类 Cloud Shell 控制台（netboot 救砖）
13. 面板 MFA 登录、前端实时查看后端日志
14. Cloudflare DNS 记录分页增删改
15. Telegram 机器人简单操作、IP 信息查询与全球服务器地图
16. AI 聊天助手、Google OAuth 2.0 登录

### 运行方式与凭证处理

- **纯本地运行**：Docker 部署在本机/VPS，不连作者中心服务器（TG 机器人为可选）
- **需交出 OCI API 凭证**：是（user_ocid / tenancy_ocid / fingerprint / region + 私钥.pem）
- **凭证存放**：本地 SQLite（容器内）；作者 README 声明"无后门"
- **作者安全建议**：不要裸 HTTP（用 Nginx 反代 HTTPS）；建议密钥登录服务器防 SSH 爆破

### 安全口碑（带来源）

**核心安全事件：2026 年 8 月底大范围盗号**

- NodeSeek《提个醒甲骨文用Y探长最好先把密钥删了》(post-900494)：楼主称"最近很多用Y探长被盗号的"，建议"找不回就找客服把号封了"；有评论肯定"y探开源的，代码可审计"
- NodeSeek《甲骨文被盗号了？》(post-899637)：用户挂机抢机时"凌晨收到新用户请求加入，转头原邮箱就被改了"；攻击者利用已有 API 密钥创建用户、禁用原账户、改绑通知邮箱
- NodeSeek《盗取甲骨文账号实锤论坛用户 [已脱敏]》(post-900555)：曝光盗号者画像（论坛 / TG / GitHub 账号与域名，已脱敏）；评论推测"Y探长有漏洞，通过面板漏洞能把 Oracle 密钥拿到"（评论推测，非定论）
- NodeSeek《聊聊最近甲骨文盗号事件》(post-902947)：复盘称"某 OCI 自动化管理面板存在未授权/越权漏洞，有人编写脚本批量拖走大量挂在公网上的面板数据库与私钥文件（.pem），并改密、替换 API Key、改绑管理员邮箱"
- NodeSeek《针对于近期甲骨文账号被盗的情况收集》(post-903098)："公网资产查询约 1k 台服务器部署了（Y探长），都存在被盗号的风险"
- 蓝点网《近期大量甲骨文云(OCI)账号被盗》(landian.news/archives/126541.html)："**实际上 R 探长没问题，被扒的是 Y 探长**"；并指出两工具都基于 OCI API、用户必须提供密钥对，权限取决于生成密钥时的配置
- NodeSeek《卧槽, Y探长盗号事件都过这么久了还有人在用Y?》(post-959772)：评论称"y探长出过两次问题，一次是几个月前说可能有漏洞但结论是没问题，一次是 8 月末被人为利用盗号"
- NodeSeek《保护你的甲骨文，护住龟壳，请马上操作》(post-960331)："Y 探长上次大范围被盗事件还在持续发酵"，建议删除全权 API Key、改用仅开机权限 Key

**公开漏洞**

- **CVE-2025-13875**（路径遍历 CWE-22）：影响 oci-helper ≤ 3.2.4，`OciServiceImpl.java` 的 `addCfg`（OCI 配置上传）函数，可远程利用，exploit 已公开；厂商被提前联系但未回应。来源：cve.org / NVD / Xzzz111/exps 披露报告 / dbugs PT-2025-48698（已多方核验为真）

**其他社区**：hostloc、知乎、酷安、吾爱破解**未找到可靠信息**；V2EX 仅一篇新手帖提及抢机机器人，未涉及安全评价。

## 二、R探长

### 基本信息

| 项 | 内容 |
|---|---|
| 全名/项目名 | **R-Bot / R探长Bot**（亦称 R Detective） |
| GitHub | https://github.com/semicons/java_oci_manage（约 2.1K stars） |
| 作者 | GitHub 用户 semicons（真实身份未找到可靠信息）；TG 频道 @agentONE_R、机器人 @radiance_helper_bot |
| 主要用途 | 起源于 OCI 抢机/开机管理，新版扩展为多云（OCI/AWS/GCP/Azure/DigitalOcean/SolusVM/VirtFusion）的 Web SSH 终端 + 云管理面板 |
| 商业模式 | 基础免费，"闪电功能"付费（NieGe Meta 2026-03 盘点："几乎重点的功能都需要付费"） |
| 是否开源 | **争议/基本不可审计**：仓库公开但核心客户端走 Release 二进制分发（r_client.jar）；历史 README 明写"**暂未开源，介意请千万勿使用**"；NodeLoc、NieGe Meta 均标注"不开源" |

### 核心功能清单

1. 开机（AMD/ARM/Intel，自定义开机、自适应 AD 开机）
2. 一键查询/更改 IP，更换 IP 自动更换域名解析
3. 修改硬盘大小和性能、删除硬盘
4. 升级/降级实例、修改实例名称、开关实例监控
5. 终止实例、TG 通知
6. 开放安全组（一键放行所有 IPv4 端口）
7. **云账户管理**：修改租户名/邮箱、添加管理员用户、删除用户、重置密码
8. Cloudflare 快捷操作（IP 绑定域名）
9. 查询账户已用流量、配额、甲骨文订阅信息
10. 一键附加 IPv6 / IPv4（多 IP）/ 预留 IP
11. 自动监控更换 IP、无公网启动 bot
12. **Web SSH 智能终端**：多标签页、SFTP 文件管理/在线编辑、端口转发、SSH 断线自动重连、批量命令工作流
13. **流量守护**：当月流量超设定值自动关停全部实例并 TG 通知
14. 试用期强开 ARM、终端预测回显、收藏命令云同步、云配置在线编辑
15. TG 机器人 30+ 云操作

### 运行方式与凭证处理

- **双端架构（必须连接开发者运营的 TG 机器人）**：本地 Java 客户端（端口 9527）+ TG 机器人驱动；部署需关注频道并向机器人发 `/raninfo` 生成账密
- **需交出 OCI API 凭证**：是（同样 user_ocid/tenancy/fingerprint/region + 私钥）
- **凭证存放**：客户端本地（`client_config` + `key.pem`）；作者声明"机器人不存储任何敏感数据……你可以随时关闭服务"（作者单方声明，未经独立审计）
- **关键区别**：与 Y探长纯本地不同，R探长的操作链路经过开发者的 TG 机器人，信任完全基于作者声明

## 三、对比小结

| 维度 | Y探长 (oci-helper) | R探长 (R-Bot) |
|---|---|---|
| 开源 | ✅ Apache 2.0，可审计 | ❌ 核心客户端闭源，不可审计 |

## 四、TriCloud 缺失功能对照（带风险评级）

> 风险定义：**高**=需交出高权限凭证/存储高敏密钥/有盗号前科的架构；**中**=破坏性操作或需第三方 Token 或 ToS 灰色；**低**=只读或用户主动的非破坏性操作

### 值得补（低风险，高价值）

| 功能 | 来源 | 风险 | 说明 |
|---|---|---|---|
| 面板 MFA 登录 | Y探长 | 低 | 安全增强，TriCloud 当前只有密码 |
| 流量守护（超量自动关停+TG 通知） | R探长 | 低 | 防流量超额扣费，TriCloud 只有告警无自动关停 |
| 断点续抢（重启后自动继续） | Y探长 | 低 | TriCloud 抢机中断后无自动恢复 |
| 实时流量统计 | Y探长 | 低 | 只读展示 |
| OCI 配额/订阅信息查询 | R探长 | 低 | TriCloud 只有 AWS 配额 |
| 加密备份恢复 | Y探长 | 低 | 配置备份，TriCloud 无 |
| 一键放行端口 / 安全列表管理 | 两者 | 低-中 | 用户主动操作；TriCloud 仅 Azure 有流量规则 |

### 谨慎评估（中风险）

| 功能 | 来源 | 风险 | 说明 |
|---|---|---|---|
| Cloudflare DNS 增删改 | 两者 | 中 | 需用户交出 CF API Token（TriCloud 有 CF 技能但未集成面板） |
| 磁盘扩容/缩小/删除 | 两者 | 中 | 破坏性操作，需二次确认 |
| 试用期强开 ARM | R探长 | 中 | ToS 灰色地带，可能导致封号 |
| 按 CIDR 换 IP / 自动监控换 IP | 两者 | 低-中 | 功能本身低风险，频繁换 IP 可能触发风控 |

### 不建议做（高风险）

| 功能 | 来源 | 风险 | 说明 |
|---|---|---|---|
| **Web SSH 终端**（SFTP/端口转发/批量命令） | R探长 | **高** | 需存储用户服务器 SSH 密钥=完整服务器权限；R探长此功能还经过其 TG 机器人 |
| **云账户用户管理**（改邮箱/加管理员/重置密码） | R探长 | **高** | 最高权限操作；正是 2026-08 盗号事件中攻击者利用的路径（改绑邮箱、创建用户） |
| 类 Cloud Shell 远程控制台 | Y探长 | **高** | 等同完整主机访问 |
| 任何"双端+作者服务器"架构 | R探长模式 | **高** | 与 TriCloud"凭证不出本地"的核心原则冲突 |

## 五、给 TriCloud 的安全启示

1. **2026-08 事件的根因是"面板裸奔公网 + 漏洞"**：攻击者批量拖走公网暴露面板的 SQLite 与.pem。TriCloud 当前部署（127.0.0.1 + Cloudflare Tunnel，无公网端口）已天然免疫这一攻击路径——**保持这个部署方式，不要改成公网直接暴露**。
2. **最小权限 API Key 是社区血泪共识**：TriCloud 可在添加 OCI 账号时提示用户使用仅开机权限的 Key，而非全权 Key。
3. **Y探长的 CVE-2025-13875 是文件上传路径遍历**：TriCloud 无类似上传接口，但可引以为戒——所有用户输入拼文件路径的地方都要校验。
4. **R探长"没翻车"靠的是作者自律+用户最小权限**，而非可审计性。TriCloud 的"开源可审计 + 凭证不出本地"路线在安全模型上更优，这是开源时值得在 README 里写明的差异点。

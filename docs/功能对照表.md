# TriCloud 功能对照表（最终汇总）

**日期**：2026-10-10
**输入**：sijuly-research.md（Oracle/aws/azure/tgbot 四仓库）、probe-tools-research.md（Y探长 oci-helper / R探长 R-Bot）、panel-research-2026-10-10.md（Komiser / ManageIQ / CloudExplorer Lite / Polynimbus / Cloudforet / azure-manager）
**口径**：三份报告"TriCloud 缺失功能"章节的全部条目，去重合并后按 ✅ 值得补 / ⚠️ 可选 / ❌ 不建议做 三类分组。

**评级调整说明**（交叉验证后对原报告评级的修正）：
1. **Cloudflare DNS 集成**：sijuly/Oracle、Y探长、R探长三处提及，合并为一条。sijuly 标"值得补"，probe 标"中风险（需 CF Token）"——定为 P2，风险通过"CF Token 仅授 DNS 编辑权限 + Fernet 本地加密存储"化解。
2. **试用期强开 ARM**：probe 原列"谨慎评估（中风险）"，但其风险实质是 ToS 灰色 + 封号，符合本次红线定义，**上调至 ❌ 不建议做**。
3. **面板本地 MFA（TOTP）** 与 **ManageIQ 的 LDAP/SAML/OIDC 企业认证源对接** 拆分为两项：前者低风险值得补，后者过度设计不建议。
4. probe 报告"安全启示"一节的两条可操作项（OCI 最小权限 Key 提示、路径遍历防护加固）补入 ✅ 表，出处单独标注。
5. 末尾两条补充自各报告功能清单细节（非缺失章节条目），单独标注出处。

## 一、✅ 值得补（高价值、低风险）

| 功能 | 出处 | 建议 | 理由 |
|---|---|---|---|
| 登录失败限速/锁定 + 登录审计 | panel/azure-manager | **P0 安全刚需** | TriCloud 2026-10-03 安全审计已明确指出"登录接口无失败限速"是已知风险；azure-manager 已有成熟实现（5 分钟 5 次 / 15 分钟 10 次锁 15 分钟），纯后端逻辑，无云 API 调用，零成本零风险 |
| 操作审计日志 + 首次登录强制改密 | sijuly/azure | **P0 安全刚需** | sijuly 报告将"借鉴操作审计日志与 admin 首次登录强制改密"列为其 P0 安全对齐建议；TriCloud 有任务历史但缺"谁在何时做了什么"的审计维度；sijuly azure 仓库是四个仓库中安全实践最好者（Fernet 密钥 0600、bcrypt、JWT、审计日志） |
| 路径遍历防护加固（文件/路径拼接接口） | probe-tools §五（CVE-2025-13875 启示） | **P0 安全刚需** | Y探长的 CVE-2025-13875（CWE-22 路径遍历，影响 oci-helper ≤3.2.4，`OciServiceImpl.java` 的 `addCfg` 配置上传函数，exploit 已公开、厂商被联系后未回应）即文件上传接口被远程利用的实例；TriCloud 目前无上传接口，属预防性加固：所有用户输入拼文件路径处必须做路径校验 |
| 闲置资源识别 / 成本优化建议 | panel/Komiser、CloudExplorer Lite、Cloudforet | **P1 高频刚需** | 三个项目交叉验证（Komiser 4145★ 核心竞争力即闲置/无标签资源识别）；用户成本敏感（曾追查 $0.16 账单到 16 次 API 调用）；实现为规则判断（长期低 CPU、已停止仍计费的实例），只读 API，低风险高价值 |
| 流量守护（月流量超阈值自动关停全部实例 + TG 通知） | probe/R探长 | **P1 高频刚需** | 防流量超额扣费的成本护栏；TriCloud 目前只有告警、无自动关停；R探长该功能已验证，报告评低风险 |
| 断点续抢（配置与任务存本地 DB，重启后自动继续抢机） | probe/Y探长 | **P1 高频刚需** | 抢机是 TriCloud 招牌功能；Y探长已实现（任务存本地 DB，服务重启自动继续）；TriCloud 抢机中断后无自动恢复，是可靠性闭环 |
| API Token 管理（正式 API Key，哈希存储，供 Android App 调用） | sijuly/azure | **P1 高频刚需** | TriCloud Android App 直连 API 目前靠面板密码 Cookie，不干净；正式 Token 机制（哈希存储）更安全的闭环，同时方便二次开发 |
| 面板 MFA 登录（本地 TOTP 二次验证） | probe/Y探长 | **P1 高频刚需** | 安全增强，TriCloud 当前只有密码；Y探长已实现面板 MFA。注意与 ManageIQ 的 LDAP/SAML/OIDC 企业对接不同，本地 TOTP 无外部依赖（后者见 ❌ 表） |
| OCI 账号最小权限 Key 提示（添加账号时引导用户用仅开机权限 Key） | probe-tools §五 | **P1 高频刚需** | 2026-08 大范围盗号后社区血泪共识（NodeSeek 多帖建议删除全权 API Key、改用仅开机权限 Key）；提示成本极低，显著缩小凭证泄露的爆炸半径 |
| Cloudflare DNS 集成（记录增删改 + 换 IP/抢机成功自动更新 A 记录） | sijuly/Oracle、probe/Y探长+R探长 | **P2 体验增强** | 三处来源合并；sijuly 评"值得补"：TriCloud 有 OCI 自动抢机，补上 DNS 联动即完整闭环；风险点（probe 标中：需第三方 Token）通过仅授 DNS 编辑权限 + Fernet 本地加密存储化解 |
| 批量操作（批量启停、批量打标签） | panel/ManageIQ、Polynimbus | **P2 体验增强** | 多账号场景省时；复用现有单实例 API 循环调用即可；TriCloud 已有批量添加账号，补批量操作成闭环 |
| OCI 配额 / 订阅信息查询 | probe/R探长 | **P2 体验增强** | TriCloud 只有 AWS 配额（Standard vCPU 全区域最大 + CloudFront）；OCI 侧补齐为只读查询，与现有配额功能对齐 |
| 实时流量统计（分钟级） | probe/Y探长 | **P2 体验增强** | 只读展示；注意轮询频率需克制——用户成本敏感，频繁调用指标 API 本身有调用成本 |
| 加密备份恢复（配置加密备份/恢复） | probe/Y探长 | **P2 体验增强** | TriCloud 无配置备份；本地 SQLite 备份 + 加密即可实现，防配置丢失 |
| 账号连通性检测（添加账号时先测连通，不通不入库） | sijuly/azure | **P2 体验增强** | 减少无效账号；纯连通性探测，无破坏性 |
| 一键放行端口 / OCI 安全列表管理 | probe/Y探长+R探长 | **P2 体验增强** | 用户主动操作（报告评低-中风险）；TriCloud 仅 Azure 有流量规则，OCI 侧补齐；放行全部端口属高危操作需二次确认 |
| Swagger API 文档 | sijuly/azure | **P2 体验增强** | 零风险，方便二次开发与 Android App 对接；sijuly azure 仓库已内嵌 |
| 创建失败自动清理（避免残留资源计费） | panel/azure-manager（§2.6 功能细节，补充项） | **P2 体验增强** | azure-manager 的亮点：创建失败自动清理避免残留计费；直击成本敏感原则，实现简单 |

## 二、⚠️ 可选（看情况）

| 功能 | 出处 | 建议 | 理由 |
|---|---|---|---|
| 预算告警（月度预算 + 超支提醒） | panel/Cloudforet | ⚠️ 可选 | 有价值，但用户账号少、消费低，优先级低于闲置识别；适用场景：后续消费上升或账号规模扩大时再加 |
| 实例性能监控图表（CPU/内存趋势） | panel/ManageIQ、azure_cloud_dashboard | ⚠️ 可选 | CloudWatch/GetMetricData 有免费额度，但增加 API 调用复杂度与成本（与成本敏感原则需权衡）；TriCloud 已有账号级监控，实例级是增强；适用场景：需要排障性能数据时 |
| 邮件通知渠道 | panel/ManageIQ | ⚠️ 可选 | 目前仅 Telegram；多渠道是加分项非必需；适用场景：TG 不可达时需要备用通知渠道 |
| 模板化 / 服务目录式创建 | panel/ManageIQ | ⚠️ 可选 | TriCloud 已有基础创建 + 默认创建参数；服务目录是企业级形态，个人用处不大；适用场景：创建模板需求频繁时 |
| 多资源类型清单（数据库/DNS/对象存储） | panel/Polynimbus | ⚠️ 可选 | 信息聚合价值有，但超出"服务器管理"核心定位；适用场景：想扩展为全资源总览时 |
| 对象存储自动本地备份 | panel/Polynimbus（§2.4 功能细节，补充项） | ⚠️ 可选 | 适用场景：有重要数据需本地冗余备份时；需额外存储与调度逻辑，非核心 |
| 代理管理（HTTP/SOCKS5，面板经代理访问云 API） | sijuly/azure | ⚠️ 可选 | 适用场景：网络环境需代理才能访问云 API；对一般用户增加复杂度无收益 |
| Azure Foundry（AI）管理（配额层级/创建 AI Services/批量部署模型） | sijuly/azure | ⚠️ 可选 | 适用场景：用户使用 Azure AI 服务；不用则无意义 |
| 初始化脚本模板（cloud-init/PowerShell） | sijuly/azure | ⚠️ 可选 | 适用场景：频繁创建实例需统一初始化；TriCloud 创建流程如已有自定义能力则可跳过 |
| TG Bot 内纯按钮交互式创建实例 | sijuly/tgbot | ⚠️ 可选 | 适用场景：希望完全脱离 Web 面板操作；TriCloud TG Bot 已有实例操作，补创建流程体验更好但非刚需 |
| 磁盘扩容/缩小/删除 | probe/Y探长+R探长 | ⚠️ 可选 | 破坏性操作（报告评中风险），必须二次确认；适用场景：存储调整刚需时；实现需严格确认流程与误操作防护 |
| 按 CIDR 换 IP / 自动监控换 IP | probe/Y探长+R探长 | ⚠️ 可选 | TriCloud 已有换公网 IP；增强为按 CIDR 段排除 / 自动监控换；低-中风险：频繁换 IP 可能触发云厂商风控；适用场景：IP 被封需自动切换时 |

## 三、❌ 有风险不建议做

| 功能 | 出处 | 建议 | 理由 |
|---|---|---|---|
| Web SSH 终端（SFTP 文件管理/在线编辑/端口转发/批量命令） | probe/R探长 | ❌ 权限风险 | 需存储用户服务器 SSH 密钥 = 完整服务器权限，面板一旦被突破即沦陷全部服务器；R探长此功能还经过其 TG 机器人，链路暴露面更大 |
| 云账户用户管理（改租户名/邮箱、添加管理员、删除用户、重置密码） | probe/R探长 | ❌ 权限风险 | 最高权限操作；**正是 2026-08 大范围盗号事件中攻击者利用的路径**——利用已有 API 密钥创建用户、禁用原账户、改绑通知邮箱（NodeSeek post-899637 实锤） |
| 类 Cloud Shell 远程控制台（netboot 救砖） | probe/Y探长 | ❌ 权限风险 | 等同完整主机访问权限，与个人轻量面板定位不符 |
| "双端 + 作者服务器"架构（本地客户端 + 开发者 TG 机器人驱动） | probe/R探长模式 | ❌ 架构冲突 | 与 TriCloud"凭证不出本地"核心原则直接冲突；操作链路经开发者服务器，信任完全基于作者单方声明（"机器人不存储任何敏感数据"未经独立审计）；R探长核心客户端 r_client.jar 闭源分发，历史 README 明写"暂未开源，介意请千万勿使用" |
| 试用期强开 ARM | probe/R探长 | ❌ ToS 灰色 | 报告明确指出属 ToS 灰色地带、可能导致封号；为免费额度冒封号风险与用户原则相悖（原报告列"谨慎评估"，按红线定义上调） |
| Tinyproxy 固定出口 IP 服务 | sijuly/aws | ❌ 与个人定位冲突 + 滥用风险 | 易被用于绕过风控/滥用，且与面板定位无关（sijuly 报告原文） |
| Bedrock Claude 可用性检测脚本 | sijuly/aws | ❌ 与个人定位冲突 | 小众需求，与面板核心无关 |
| SSH Key 明文管理（照搬 sijuly 方案） | sijuly/Oracle | ❌ 安全风险 | 功能本身可做，但 sijuly 将凭证明文存储是反面教材（其 OCI 私钥明文存 `oci_profiles.json`、TG/Cloudflare token 明文存 JSON）；若实现必须 Fernet 加密，照搬明文方案等于主动引入高危 |
| 完整 RBAC / 多租户 / 多人协作 | panel/ManageIQ、CloudExplorer Lite、Cloudforet | ❌ 复杂度失控 + 与个人定位冲突 | TriCloud 是个人自用面板；引入用户/角色/组织体系将大幅增加复杂度，且与"凭证自己掌控"的单用户定位冲突（panel 报告原文） |
| LDAP/AD/SAML/OIDC 外部认证源对接 | panel/ManageIQ | ❌ 架构冲突（过度设计） | 企业级身份源对接，个人面板过度设计；当前 PBKDF2 + 会话机制已够用（注意与本地 TOTP MFA 区分，后者值得补） |
| Chargeback 费率体系 / 成本分账 | panel/ManageIQ、CloudExplorer Lite | ❌ 与个人定位冲突 | 企业财务分摊场景，个人用户用不上 |
| 安全合规扫描引擎 | panel/CloudExplorer Lite | ❌ 复杂度失控 | 需自建规则引擎，复杂度高；个人账号合规需求低 |
| 编排栈管理（CloudFormation/Heat） | panel/ManageIQ | ❌ 与个人定位冲突 | 属 IaC 范畴，与"管理面板"定位不符 |
| SNMP Trap 告警 | panel/ManageIQ | ❌ 与个人定位冲突 | 企业监控对接方式，个人场景无接收端 |

## 总体结论

**1. TriCloud 相对这些面板的差异化优势**

- **定位优势**：唯一的"个人自用、三云可操作、轻量"面板。Komiser/Cloudforet 偏只读分析或企业平台（Cloudforet 需 K8s+gRPC 微服务、ManageIQ 需 PostgreSQL+Redis 企业级栈），sijuly/aws 无账单无监控无通知，Y探长仅 OCI 且有 CVE-2025-13875 前科，R探长核心闭源且依赖作者 TG 机器人。
- **功能优势**：OCI 换公网 IP/分配 IPv6/改配置/自动抢机、AWS Lightsail 与 CloudFront 管理、Standard vCPU 全区域配额查询、Azure deallocate/换 IP 重建 PIP/resize/流量规则、三云账单 + AWS 手动 Credit + 账单节流、TG Bot 交互 + 每日账单报告 + 实例异常告警、回收站、任务历史、深浅色主题——在"个人多云操控"定位上比所有调研项目更贴合。
- **安全模型优势**：Fernet 加密存本地 + PBKDF2 + 127.0.0.1 + Cloudflare Tunnel 部署，天然免疫 2026-08 大范围盗号的攻击路径（攻击者批量拖走公网暴露面板的 SQLite 与 .pem 文件，NodeSeek post-902947）；凭证全面优于 sijuly 系列（明文 JSON/key.txt/硬编码弱口令 （三个硬编码弱口令，原文已脱敏））；开源可审计路线优于 R探长"闭源客户端 + 作者服务器"的信任模型。

**2. 最值得补的前 5 项（排序）**

1. **登录失败限速/锁定 + 登录审计**——自己 2026-10-03 安全审计已标记的已知风险，azure-manager 有现成参数（5 分钟 5 次 / 15 分钟 10 次锁 15 分钟），纯后端零成本。
2. **操作审计日志 + 首次登录强制改密**——sijuly 报告的 P0 安全对齐建议，补上"谁在何时做了什么"维度。
3. **闲置资源识别 / 成本优化建议**——三份面板报告交叉验证，直击成本敏感原则，只读 API 低风险。
4. **流量守护（超量自动关停 + TG 通知）**——从"事后告警"升级为"事前止损"的成本护栏。
5. **断点续抢**——抢机是招牌功能，重启后自动继续是可靠性闭环，Y探长已有成熟实现可参考。
   （下一顺位：API Token 管理，闭合 Android App 直连的安全闭环。）

**3. 绝对不要碰的红线清单**

- **主机级远程控制**：Web SSH 终端（SFTP/端口转发）、类 Cloud Shell 控制台——需存 SSH 密钥 = 完整服务器权限。
- **云账户用户管理**：改邮箱/加管理员/重置密码——正是 2026-08 盗号事件中攻击者使用的精确路径。
- **"双端 + 作者服务器"架构**：凭证永不出本地；保持 127.0.0.1 + Cloudflare Tunnel 部署，绝不公网裸奔（公网资产查询约 1k 台暴露面板被批量拖库的教训，NodeSeek post-903098）。
- **ToS 灰色操作**：试用期强开 ARM——封号风险。
- **易被滥用功能**：Tinyproxy 固定出口 IP。
- **任何明文凭证方案**：sijuly 的 `key.txt`/`oci_profiles.json`/硬编码弱口令是反面教材；一切凭证必须 Fernet 加密。
- **企业级复杂度**：RBAC/多租户/LDAP/SAML/Chargeback/合规扫描引擎——稀释"轻量个人面板"定位。
